  • apiFetch: cookies ride along (credentials: 'include'); POST / PUT add X-XSRF-TOKEN and Content-Type: application/json; a 401 refreshes the session once and replays. dms-core/src/lib/auth.ts:205-227

  • Who may call: reads need DEALER, STATE, HO or ADMIN (@DealerAndAbove on the controller, AreaMasterController.java:31); POST / PUT need HO or ADMIN (@HeadOfficeAndAbove, lines 65, 72). There is no DELETE: masters are never deleted.

  • Procedure errors: a RAISERROR (error 50000) comes back as a 400 with its text (AreaProcedures.java:190-199). USP_TEHSIL_CRUD / USP_CITY_CRUD / USP_PIN_CRUD answer an error with an ErrorMessage row instead; that row becomes the same 400 (written(), 173-183).

  • Path roots: frontend paths start at THRSL_SCMS_FRONTEND/projects/; backend paths starting areaMaster/ are under THRSL_SCMS_BACKEND/masters-service/src/main/java/com/itl/dms/mastersservice/modules/.

Gotchas

  • USP_SEARCH_CITY reads MASTERDATA.CITY, which does not exist (CM_CITY is the table; lines 48, 94, 129 of its script). Until it is fixed, masters-service reads CM_CITY directly for the City list and SEARCH (AreaMasterService.java:243-294). The ready fix: db-fix-usp-search-city.sql.
  • Editing a tehsil or city fails unless its code changes. The UPDATE duplicate check of USP_TEHSIL_CRUD / USP_CITY_CRUD does not leave out the row itself, so it finds the row being edited: "Tehsil_Code already exists for this district." Fix: add AND tehsil_id <> @tehsil_id / AND city_id <> @city_id to that check.
  • A PIN code cannot repeat within a city on Add. USP_PIN_CRUD's INSERT still blocks the same pin_code in the same city; its UPDATE check is commented out, so an Edit can make a duplicate. To allow one PIN for several post offices, add AND post_office = @post_office to the INSERT check.
  • Tehsil and City codes are numbers. The CRUD procedures take them as INT, so the form and masters-service accept digits only (at most 9).
  • USP_GETDROPDOWNDATA still names some pre-rename columns: 'C' excludes CreatedDate … (now Created_Date …), so Country's Search On also offers the audit columns (the screen drops them); 'Z' and 'S' look for CountryDesc (now Country_Desc), so neither offers a Country choice.
  • USP_ZONE_CRUD's parameters were renamed on 08 Oct (@ZONE_NAME, @IS_ACTIVE, @CREATED_BY …). masters-service sends the new names (AreaProcedures.java:59-66); a build from before that change fails every Zone save.
  • The procedure lists page. Called with page 0 / size 0 they return 20 rows; masters-service asks for page 1 of 2147483647 rows, so the lists and searches hold every row.
  • New Tehsil / City / Pin rows get NULL MIBL_FLAG and Project_ID; an edit sends the row's own back, as the procedures overwrite them.
  • The customer screens' City / Tehsil lookups (lookupMaster, not these masters) still assume the old hierarchy and column names.
